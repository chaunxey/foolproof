# Feature Specification: 重复照片清理（duplicate-cleanup）

**Feature Branch**: `feature_foundation1`（目录：`specs/003-duplicate-cleanup`）

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "重复照片清理：本地扫描相册，用感知哈希分组，用户确认后删除重复项"

## 概述

用户在「图片压缩」tab 的下半屏点【查询相同图片】，应用扫描相册、用感知哈希把近似重复的照片分组，
按组展示每组占用与可释放空间；用户勾选要删的项并二次确认后删除。

三条硬边界（均来自宪法）：

- **完全本地**，不联网、不上传（§1.2）；
- **绝不自动删除**：任何删除都必须经用户勾选 + 二次确认（§3.2）；
- **删除按 API 分通道**：API 30+ 走系统回收站（可恢复），API 24–29 走 SAF 且**不可恢复**（§3.2 v1.6）。

本模块只提供同页的下半部分（`DuplicateSection`），整页与压缩区的组装由 `:app` 负责（§3.2，v1.4/v1.8）。

## User Scenarios & Testing

### User Story 1 - 扫描并分组展示重复照片 (Priority: P1)

用户点【查询相同图片】，首次使用时应用请求相册读取权限；授予后开始扫描并显示进度，
完成后按组展示重复照片，每组显示张数与可释放空间。

**Why this priority**: 没有分组结果，后续的勾选与删除都无从谈起。

**Independent Test**: 在一个含 3 组重复（每组 2–4 张）与若干独图的测试相册上扫描，
断言分组数、每组成员与预期的可释放空间一致。

**Acceptance Scenarios**:

1. **Given** 首次使用且未授权，**When** 点【查询相同图片】，**Then** 弹出相册读取权限请求；拒绝则提示且不开始扫描。
2. **Given** 已授权，**When** 开始扫描，**Then** 显示扫描进度（已扫描数/总数），界面不卡顿。
3. **Given** 扫描完成，**When** 查看结果，**Then** 按组展示，每组头部显示「N 张 · 可释放 X MB」。
4. **Given** 相册中没有重复，**When** 扫描完成，**Then** 明确提示「没有发现重复照片」。
5. **Given** 扫描进行中，**When** 点取消，**Then** 立即停止并保留已发现的分组。

---

### User Story 2 - 勾选并删除重复项 (Priority: P1)

每组默认预选「除最大一张以外的其余项」，用户可逐张改选；点【删除】后弹出确认框，
确认后执行删除，完成后该组只保留未勾选的图片。

**Why this priority**: 这是功能的全部价值；但必须先有分组（US1）。

**Independent Test**: 在 1 组 3 张的测试相册上，断言默认预选为「2 张较小的」；
改选后删除，再查询相册确认只剩预期的一张。

**Acceptance Scenarios**:

1. **Given** 一组 3 张，**When** 首次展示，**Then** 自动勾选除最大外的 2 张（最大者默认保留）。
2. **Given** 用户改选，**When** 勾选状态变化，**Then** 删除按钮上的数量与总大小实时更新。
3. **Given** 有勾选，**When** 点【删除】，**Then** 弹出确认框，显示「将删除 N 张，约 X MB」；
   API ≤ 29 时额外提示「低版本删除后无法恢复」。
4. **Given** 用户在确认框点取消，**When** 返回，**Then** 不删除任何文件，勾选状态保留。
5. **Given** 用户确认删除，**When** 执行完成，**Then** 整组消失或只剩未勾选的图片，并汇总「已删除 N 张，失败 M 张」。

---

### User Story 3 - 全屏查看大图 (Priority: P2)

用户点任意一张图片，进入全屏预览，可看清细节再决定删不删。

**Why this priority**: 删除是不可逆操作，看清楚是安全前提；但没有它也能用。

**Independent Test**: 点图后断言进入全屏、可左右切换到同组其他图、返回后勾选状态不变。

**Acceptance Scenarios**:

1. **Given** 结果列表，**When** 点某张图，**Then** 全屏显示该图并可缩放/滑动查看。
2. **Given** 全屏预览，**When** 返回，**Then** 回到列表且勾选状态保持。

---

### User Story 4 - 低版本（API 24–29）的降级路径 (Priority: P2)

低版本没有系统回收站 API，删除改走 SAF：用户先授权一个目录，删除后不可恢复，界面必须说清楚。

**Why this priority**: 保证低版本用户不被卡死，但主路径在 API 30+。

**Independent Test**: 在 API 29 模拟器上断言删除按钮在未授权时置灰、授权后可用、确认框含「不可恢复」警告。

**Acceptance Scenarios**:

1. **Given** API ≤ 29 且未授权目录，**When** 查看结果，**Then** 删除按钮置灰并说明原因。
2. **Given** 已授权 SAF 目录，**When** 执行删除，**Then** 文件被删除且界面提示「已删除，无法恢复」。

---

### 边界情况

- **权限被永久拒绝**：提示并提供「去系统设置」的入口，不再反复弹窗。
- **空相册 / 全部被跳过**：明确提示，不显示空网格。
- **超长扫描（> 5000 张）**：分批扫描、进度可见、可随时取消。
- **纯色图 / 截图**：dHash 对纯色图几乎全为 0，**极易误判**；必须用方差/尺寸等附加条件保护。
- **同图不同压缩/尺寸**：必须能被判为同组（这是主要使用场景）。
- **HEIC（API ≤ 27）**：跳过并计入「已跳过」数量，不崩溃（§3.3 门槛）。
- **删除过程中部分失败**：逐张执行，失败项保留在列表并标记原因。
- **扫描后相册变化**：结果可能过期；重新扫描即可，删除前以文件是否存在为准。
- **相册里有正在下载/损坏的文件**：解码失败则跳过，不影响整体。

## Requirements

### Functional Requirements

**模块与边界**

- **FR-001**: 系统 MUST 提供独立模块 `:features:duplicate-cleanup`，仅依赖 `:base`，不依赖其他 feature。
- **FR-002**: 本模块 MUST 只对外暴露 `DuplicateSection` 与 `DuplicateViewModel`；整页由 `:app` 组装，
  且位置在图片压缩区**之下**（宪法 §3.2 v1.8）。

**扫描与判定**

- **FR-003**: 扫描 MUST 完全本地完成，MUST NOT 发起任何网络请求。
- **FR-004**: 重复判定 MUST 使用感知哈希 + 汉明距离，距离阈值 **≤ 5**（宪法 §3.2）。
- **FR-005**: 纯色 / 低方差图片 MUST 有额外保护（例如方差阈值或宽高比 + 尺寸接近判定），
  MUST NOT 仅凭哈希距离把它们并为一组。
- **FR-006**: 扫描 MUST 分批进行并暴露进度（已扫描 / 总数），MUST 可取消，MUST NOT 阻塞主线程。
- **FR-007**: 扫描 MUST 对图片采样解码后再计算哈希（复用 `BitmapSampling` 的思路），避免大图 OOM。
- **FR-008**: HEIC 输入在 API ≤ 27 MUST 被跳过并计入跳过数，MUST NOT 崩溃（宪法 §3.3）。

**权限**

- **FR-009**: 本模块 MUST 只申请宪法 §8 允许的**读取**权限：API ≥ 33 用 `READ_MEDIA_IMAGES`，
  API ≤ 32 用 `READ_EXTERNAL_STORAGE`；MUST NOT 申请任何写权限。
- **FR-010**: 首次扫描前 MUST 请求权限；被拒绝时 MUST 给出可操作提示；永久拒绝 MUST 提供跳转系统设置。

**展示与勾选**

- **FR-011**: 结果 MUST 以三列网格展示，组头跨列且显示张数与可释放空间；
  Section MUST NOT 自带滚动容器（整页滚动由 `:app` 统一管理，宪法 §3.2 v1.11）；
  缩略图 MUST 按原图比例完整显示，MUST NOT 裁剪。
- **FR-012**: 每组 MUST 默认预选「除最大一张以外的其余项」，用户 MUST 可逐张改选；
  系统 MUST NOT 在无用户确认的情况下删除任何文件。
- **FR-013**: 点图片 MUST 进入全屏预览，返回后勾选状态 MUST 保持。

**删除**

- **FR-014**: 删除前 MUST 弹出二次确认，显示即将删除的张数与总大小；
  API ≤ 29 时 MUST 额外明示「删除后无法恢复」。
- **FR-015**: API ≥ 30 MUST 通过系统删除请求（进回收站、可恢复）；API ≤ 29 MUST 走 SAF，
  且未授权目录时删除入口 MUST 置灰并说明原因（宪法 §3.2 v1.6）。
- **FR-016**: 单张删除失败 MUST NOT 影响其余项；批次结束 MUST 汇总成功/失败数量。

**质量**

- **FR-017**: 哈希计算、分组算法（阈值边界）、预选规则、状态机、失败隔离 MUST 有单元测试，
  `./gradlew :features:duplicate-cleanup:testDebugUnitTest` 通过。
- **FR-018**: ViewModel MUST 继承 `BaseViewModel`（宪法 §4）；日志 MUST 用注入的 `LogUtil`（§6）。

### Key Entities

- **PhotoItem**：相册中的一张图（id、显示名、字节数、宽高、修改时间、哈希值、可读状态）。
- **PhotoGroup**：一组判定为重复的图（代表哈希、成员列表、总字节、可释放字节）。
- **ScanState**：`Idle` / `RequestingPermission` / `Scanning(scanned, total)` / `Done` / `Cancelled` / `Failed`。
- **SelectionState**：每张图的勾选状态 + 派生「待删除张数与字节数」。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 1000 张照片的相册，扫描在 60 秒内完成（中端机），全程 UI 可交互。
- **SC-002**: 同一张照片的 3 个压缩版本（原图 / 80% 质量 / 50% 质量）**必须**落入同一组。
- **SC-003**: 构图不同的照片**不得**被误分到同一组（用固定测试集验证，误判 0 组）。
- **SC-004**: 全工程检索 `WRITE_EXTERNAL_STORAGE`，本模块相关代码与 manifest **0 处**。
- **SC-005**: 任何删除路径都必须先出现确认框（可用 UI 测试或人工清单验证）。
- **SC-006**: API ≥ 30 删除的图片可在系统回收站中恢复。

## 假设

- **哈希算法**：8×8 dHash（64 bit，灰度），阈值 5；不引入第三方哈希库。
- **分组方式**：流式贪心——每张新图与已有组的代表哈希比较，命中则入组，否则新建组。
- **扫描范围**：整个相册（含子目录），不按日期过滤；单次最多扫描 20000 张，超出部分提示。
- **权限实现**：本模块内用 `ActivityResultContracts.RequestPermission` 自行处理；
  宪法 §3 提到的「权限请求基类」等 `:common` 建成后再迁移（当前 `:common` 尚未创建）。
- **预览**：Compose 全屏 + Coil 加载，不做缩放以外的编辑。
- **范围外**：视频去重、按文件夹筛选、云端相册、自动清理策略（定时任务）。

### 已定的默认（原可选项）

- **N1 扫描范围**：全相册，不提供文件夹选择（v1）。
- **N2 日期过滤**：不做（v1）。
- **N3 大相册**：全量扫描 + 分页加载展示，扫描过程显示进度。

### 需要负责人留意的一处口径

- **FR-012 的「默认预选」与宪法「必须用户手动勾选确认」之间有张力**：
  预选不等于自动删除，用户仍需点删除并二次确认；但这确实降低了「逐张手动勾选」的严格程度。
  本 spec 按负责人 2026-10-21 的决定采用「预选除最大外」；建议同步在宪法 §3.2 记一句，
  避免后续实现者按旧条文理解成「必须什么都不选」。
