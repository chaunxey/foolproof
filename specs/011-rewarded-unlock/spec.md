# Feature Specification: 激励视频解锁次数（rewarded-unlock）

**Feature Branch**: `feature/ad-sdk-provider`
**Directory**: `specs/011-rewarded-unlock`
**Created**: 2026-10-23
**Status**: Implemented（`feature/ad-sdk-provider`）
**Input**: “每天免费 5 次，0 点刷新；点击激励可以 +5，可重复；激励次数单独存在、不会被 0 点刷新掉；每天的免费 5 次不累计。”

> 级别：L2（行为变更）。按宪法 §13：spec → plan → tasks → implement → verify。
> 本 spec 取代 `010-ad-sdk-provider` 中「成功 5 次后自动弹全屏」的门控形态；
> 010 的 provider 切换、横幅、开屏不变。

## 概述

每个功能维护**两套独立额度**：

| 额度 | 规则 |
| --- | --- |
| 每日免费 | 每个功能每天 5 次；本地时区 0 点重置为 5；**不累计**（今天剩 2 次，明天仍是 5 次） |
| 激励余额 | 每看一次激励视频 +5；**可重复**；独立持久化，**不随 0 点重置**、不清零 |

可用次数 = 今日免费剩余 + 激励余额。

- 可用 > 0：正常执行；成功后扣 1（**先扣每日免费，再扣激励余额**）。
- 可用 = 0：进入锁定态，按钮文案变「看广告解锁 5 次」；点击弹确认框，
  用户主动看完激励视频 → 余额 +5 → 自动执行刚才的操作（成功后扣 1）。
- 中途关闭/跳过（无奖励回调）→ 不解锁、不执行。
- 广告加载失败/无填充/8 秒超时 → **放行当前一次**（不扣额度），
  同一功能 60 秒内再次触发直接放行。
- 跨天：App 在前后台切换或下一次操作时把每日免费刷新为 5；激励余额不动。

### 不做什么

- ❌ 不自动播放激励视频（必须用户主动触发，平台合规要求）；
- ❌ 不做积分/兑换等复杂激励体系；
- ❌ 不改横幅、开屏、provider 构建开关；
- ❌ 每日免费不做累计、不做补领。

## User Scenarios & Testing

### User Story 1 - 每日免费 5 次 (Priority: P1)

**Acceptance Scenarios**：

1. **Given** 今天还没用过某功能，**Then** 可用 5 次。
2. **Given** 今天成功用了 2 次，**Then** 剩余 3 次，按钮正常。
3. **Given** 今天 5 次用完且激励余额为 0，**When** 看按钮，**Then** 文案为「看广告解锁 5 次」。
4. **Given** 今天剩 2 次，**When** 到了第二天 0 点后首次使用，**Then** 免费额度回到 5（不是 7）。
5. **Given** 今天 5 次全用完，**When** 第二天 0 点后，**Then** 又可以免费用 5 次。

### User Story 2 - 激励余额 +5、可重复、不清零 (Priority: P1)

**Acceptance Scenarios**：

1. **Given** 可用为 0，**When** 看完一次激励视频，**Then** 余额 +5，自动执行并扣 1（剩 4）。
2. **Given** 余额 4，**When** 再成功用 1 次，**Then** 余 3。
3. **Given** 有激励余额，**When** 跨过 0 点，**Then** 激励余额保持不变。
4. **Given** 余额 4，**When** 再看完一次激励视频，**Then** 余额 +5 叠加（9，可重复）。
5. **Given** 每日免费还有剩余，**When** 成功使用，**Then** 先扣每日免费，不动激励余额。

### User Story 3 - 锁定与解锁交互 (Priority: P1)

**Acceptance Scenarios**：

1. **Given** 可用为 0，**When** 点击功能按钮，**Then** 弹确认框，不自动播广告、不执行功能。
2. **Given** 确认框，**When** 点【取消】，**Then** 关闭，功能不执行，额度不变。
3. **Given** 确认框，**When** 点【观看广告】，**Then** 加载激励视频（加载态，不可重复点）。
4. **Given** 完整看完并有奖励回调，**Then** +5、自动执行、只执行一次。
5. **Given** 中途关闭/跳过（无奖励），**Then** 不解锁、不执行，可再次尝试。

### User Story 4 - 广告失败不卡死 (Priority: P1)

1. **Given** 加载失败/无填充/超时 8 秒，**Then** 放行当前一次，不扣额度。
2. **Given** 刚失败过，**When** 60 秒内再次触发，**Then** 直接放行，不再等待。
3. **Given** 未配置广告位，**Then** 视为无广告：放行当前一次，不扣额度。

### User Story 5 - 两个 provider 行为一致 (Priority: P2)

1. **Given** `meta` 构建且配置了 Rewarded placement，**Then** 流程与 pangle 一致。
2. **Given** `pangle` 构建且广告位为激励视频，**Then** 使用 `loadRewardVideoAd` 并校验奖励回调。

## Functional Requirements

- **FR-001**：每个功能每天 5 次免费额度；按**本地时区** 0 点重置；未用完**不累计**。
- **FR-002**：激励视频每看完一次 +5 次；可重复叠加；独立持久化，**不被 0 点重置**。
- **FR-003**：可用次数 = 今日免费剩余 + 激励余额；执行成功后扣 1，**先扣免费、再扣激励**。
- **FR-004**：可用为 0 时进入锁定态；按钮文案「看广告解锁 5 次」。
- **FR-005**：锁定态点击只弹确认框，不自动播放广告、不执行功能；【取消】不改变额度。
- **FR-006**：【观看广告】后才加载并展示激励视频；加载中显示加载态，不可重复触发。
- **FR-007**：只有奖励回调为真才 +5 并解锁；关闭/跳过/失败都不解锁。
- **FR-008**：奖励成功后自动执行本次操作，只执行一次，并按 FR-003 扣 1。
- **FR-009**：广告加载失败、无填充或 8 秒超时：放行当前一次且不扣额度；
  同一功能 60 秒内再次触发直接放行（失败冷却）。
- **FR-010**：未配置广告位时视为无广告：放行当前一次且不扣额度。
- **FR-011**：跨天刷新 MUST 惰性完成（读取/操作/回前台时）——无需后台定时器；
  刷新后 UI 的锁定态 MUST 同步更新。
- **FR-012**：`AdGate` 契约扩展为「可用次数 / 是否锁定 / 主动解锁」；
  5 个功能（图片压缩、重复清理、视频压缩、视频拼接、文件转换）全部接入。
- **FR-013**：Meta 与穿山甲都实现激励加载器（Meta `RewardedVideoAd`、穿山甲 `loadRewardVideoAd`）；
  Meta 新增 rewarded placement 配置位。
- **FR-014**：文案与弹窗走 `strings.xml`，覆盖 zh/en/ja/fr/de/km 六种语言。
- **FR-015**：解锁/失败/取消均不得崩溃或重复执行；SDK 回调参数必须空值防护。
- **FR-016**：MUST 有 JVM 单测覆盖：免费扣减、跨天重置且不累计、激励 +5 可重复、
  余额跨天保留、先免费后激励、失败放行、失败冷却、未配置放行、只执行一次。

## Key Entities

- **Quota**：`{ freeUsedToday, bonus, dayKey }` → `available = (5 - freeUsedToday) + bonus`。
- **GateLockState**：按 `FeatureId` 的可用次数与锁定态（`available <= 0`）。
- **RewardedAd / RewardedAdLoader**：已加载/负责加载的激励视频。
- **RewardUnlockDialog**：共享 Compose 弹窗（取消 / 观看广告 / 加载中）。

## Success Criteria

- **SC-001**：5 个功能都出现「免费 5 次 → 锁定 → 看广告 +5 → 继续用」完整链路。
- **SC-002**：跨天验证：免费额度回到 5（不累计），激励余额不变。
- **SC-003**：中途关闭广告时，功能不执行、额度不变、按钮仍为锁定文案。
- **SC-004**：断网/无填充时最多等 8 秒即放行，60 秒内不再等待。
- **SC-005**：JVM 单测全绿；meta / pangle 两个构建均通过。
- **SC-006**：无自动播放激励视频的代码路径。

## 假设

- 每日免费按**功能**独立计算（每个功能各 5 次/天），不是全局 5 次。
- 时区跟随设备本地时区。
- 消耗顺序默认「先免费、后激励」；如果产品要求反过来，改一处策略即可。
- 穿山甲 `104722138` 是激励视频广告位；Meta 需要在后台新建 Rewarded placement。
- 8 秒加载超时、60 秒失败冷却为默认值。
