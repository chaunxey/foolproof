# Feature Specification: 文件转 PDF（file-conversion）

**Feature Branch**: `feature_foundation1`（目录：`specs/005-file-conversion`）

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "图片转 PDF、文本/Markdown 转 PDF；任意文档（docx/xlsx）留到后续再做"

## 概述

把两类本地内容转成 PDF：**多张图片**（手机里的照片/截图，需要合并成一份文档）
与**纯文本 / Markdown**（如导出的笔记、日志、README）。

这是宪法 §1.1 的功能 3（多张图片合并生成 PDF）与功能 4（本地文件转 PDF），
共用 `:features:file-conversion` 模块，在底部导航占第 3 个 tab。

**本次范围**：图片 → PDF、文本/TXT/MD → PDF。
**明确不做**（后续再议）：Word（.docx/.doc）、Excel（.xls/.xlsx）、PPT、PDF 合并/拆分、OCR、PDF 编辑。

> ⚠️ 宪法 §3.3 原先把「Word（DOCX）→ PDF」标为 ✅ v1 实现（截长图方案），
> 负责人于 2026-10-21 决定**推迟到后续**。本规格按推迟后的范围编写，
> 宪法同步修订为 v1.16（见 changelog）。

## 用户故事

### User Story 1 - 多张图片合成 PDF (Priority: P1)

用户从相册选几张图片，调整顺序，生成一份 PDF，用于发送、存档或打印。

**Why this priority**: 这是最高频的场景（截图整理、证件照合并、作业拍照交作业），
且零依赖（原生 `PdfDocument`），风险最低。

**Independent Test**: 选 5 张不同尺寸的图片生成 PDF，用系统 PDF 阅读器打开，
断言页数 = 5、每页图片完整不变形、顺序与界面一致。

**Acceptance Scenarios**:

1. **Given** 未选择任何图片，**When** 查看界面，**Then** 【生成 PDF】置灰并提示先选图片。
2. **Given** 已选 5 张图片，**When** 查看列表，**Then** 显示缩略图与序号，可删除单张。
3. **Given** 已选多张图片，**When** 调整顺序后生成，**Then** PDF 页序与界面顺序一致。
4. **Given** 图片宽高比差异很大（竖图 + 横图），**When** 生成 PDF，**Then** 每张图完整显示、不变形（Letterbox 留白）。
5. **Given** 选中的图片里有 HEIC 且系统为 API 24–27，**When** 生成，**Then** 明确提示「当前系统不支持 HEIC 格式」并跳过该张，其余照常生成，不崩溃。
6. **Given** 生成过程中点【取消】，**Then** 立即停止并删除半成品 PDF。

---

### User Story 2 - 文本 / Markdown 转 PDF (Priority: P1)

用户选一个 `.txt` 或 `.md` 文件，生成排版规整的 PDF（标题层级、列表、代码块可辨认）。

**Why this priority**: 与 US1 并列的 P1——两者独立，任一缺失都让"文件转 PDF"名不副实。

**Independent Test**: 选一个含中文标题、段落、有序/无序列表、代码块的 `.md`，
生成 PDF 后用 PDF 阅读器打开，断言内容完整、无乱码、行不被截断。

**Acceptance Scenarios**:

1. **Given** 已选一个 `.md` 文件，**When** 查看界面，**Then** 显示文件名与大小。
2. **Given** Markdown 含 `#`/`##`/`###` 标题、`-` 列表、`**粗体**`、三反引号代码块，
   **When** 生成 PDF，**Then** 标题字号递减、列表带符号、粗体加粗、代码块等宽且有底色。
3. **Given** 文本含一个超长无空格串（如长 URL），**When** 排版，**Then** 在页面内强制断行，不溢出页面。
4. **Given** 文本内容超过一页，**When** 生成，**Then** 分页处不出现"半行被切断"，页码连续。
5. **Given** 文件为空或只有空白字符，**When** 尝试生成，**Then** 提示「文件没有可转换的内容」。
6. **Given** 文件不是 UTF-8 编码，**When** 读取，**Then** 尽力解码（回退 GBK 等）或明确提示编码不支持，不产出乱码 PDF。

---

### User Story 3 - 保存与应用内分享 (Priority: P2)

生成的 PDF 能立刻打开、分享给别的应用，或存到手机的下载目录。

**Why this priority**: 不能导出就等于没生成；但它依赖 US1/US2 的产物，所以排在后面。

**Independent Test**: 生成一个 PDF 后点【分享】，断言系统分享面板出现且能选中其他应用；
点【存到下载】后断言 `Downloads/Foolproof/` 下出现同名文件。

**Acceptance Scenarios**:

1. **Given** 已生成 PDF，**When** 查看结果区，**Then** 显示文件名、大小、页数，并出现【打开】【分享】【存到下载】。
2. **Given** 已生成 PDF，**When** 点【分享】，**Then** 通过 `FileProvider` 授予临时读权限，分享面板可选中其他应用。
3. **Given** 已生成 PDF，**When** 点【存到下载】（API ≥ 29），**Then** 经 `MediaStore.Downloads` 写入 `Downloads/Foolproof/`，**不申请任何写权限**。
4. **Given** 系统为 API ≤ 28，**When** 查看结果区，**Then** 不显示【存到下载】（需写权限，本应用不申请）。

---

### 边界情况

- **超大图片**：单张 > 20MP 时先采样再嵌入，避免 OOM；不得直接解码原图到内存。
- **数量上限**：单次最多 50 张图片，超出时提示并拒绝继续选择。
- **页面尺寸**：v1 固定 A4 竖版（595×842 pt），四周留 24pt 边距；不提供自定义纸张。
- **图片方向**：按 EXIF 方向修正后再嵌入，不得出现照片被旋转。
- **文件名**：输出名带时间戳（`foolproof_20261021_1530.pdf`），避免重名覆盖。
- **空间不足**：生成前检查可用空间（≥ 预估大小的 2 倍），不足时明确提示。
- **进程被杀**：上次未完成的半成品 PDF 在下次启动时清理。

## 功能需求

### 输入

- **FR-001**: 图片 MUST 通过系统 Photo Picker（`PickMultipleVisualMedia`）多选，**不申请读取权限**。
- **FR-002**: 文本/Markdown MUST 通过 SAF（`ACTION_OPEN_DOCUMENT`，`text/*` + `.md`）选择单个文件，**不申请存储权限**。
- **FR-003**: Markdown MUST 支持：`#`–`###` 标题、段落、`-`/`1.` 列表、`**粗体**`、`*斜体*`、
  `` `行内代码` ``、三反引号代码块、`---` 分隔线；其余语法按纯文本呈现。
- **FR-004**: 文本文件 MUST 限制在 2MB 以内，超出时提示"文件过大"并拒绝。

### 转换

- **FR-005**: PDF MUST 由原生 `android.graphics.pdf.PdfDocument` 生成，**不引入第三方 PDF 库**（宪法 §2）。
- **FR-006**: 图片 MUST 按原宽高比嵌入 A4 页面并居中，**不得拉伸变形**；超出页面时等比缩小适配。
- **FR-007**: 图片 MUST 先按 EXIF `Orientation` 修正方向再绘制。
- **FR-008**: 文本排版 MUST 支持中文与英文混排、自动换行、跨页分页；分页 MUST NOT 切断单行。
- **FR-009**: 页面尺寸 MUST 为 A4 竖版（595×842 pt），边距 24pt（图片）/ 48pt（文本）。
- **FR-010**: HEIC 图片在 API 24–27 MUST 提示「当前系统不支持 HEIC 格式」并跳过，不得崩溃或静默失败（宪法 §3.3）。
- **FR-011**: 转换 MUST 显示进度（当前第 x/y 页）并可取消；离开页面 MUST 取消任务。

### 输出与权限

- **FR-012**: 输出 MUST 写在应用私有目录 `files/pdf/`，分享经 `FileProvider`（authority `<包名>.files`）。
- **FR-013**: 【存到下载】MUST 仅在 API ≥ 29 出现，经 `MediaStore.Downloads` 写入，**不申请写权限**。
- **FR-014**: 取消或失败 MUST 删除半成品文件；启动时 MUST 清理上次残留（FR-012 目录下无对应结果的 `.pdf`）。

### 交互与错误

- **FR-015**: 错误 MUST 分类提示：无可转换内容 / 无法读取 / 编码不支持 / 空间不足 / 生成失败。
- **FR-016**: 转换中 MUST 禁止重复点击，参数控件置灰。
- **FR-017**: 页数 MUST 在生成后显示，便于用户确认是否完整。
- **FR-023**:（`:app` 级行为）首页按返回键 MUST NOT 立即退出：首次 MUST 提示「再按一次退出」，
  2 秒内再次返回才 `finish()`，避免误触丢失当前状态。<!-- 2026-10-21 回写：实现于 FoolproofScreen，原规格缺失 -->

### 质量

- **FR-018**: Markdown 解析、分页计算、文件名生成、EXIF 方向修正 MUST 有单元测试
  （纯逻辑不依赖 Android 运行时，能用 JVM 单测覆盖的必须覆盖）。
- **FR-019**: ViewModel MUST 继承 `BaseViewModel`（宪法 §4）；日志 MUST 用注入的 `LogUtil`（宪法 §6）；
  PDF 生成器 MUST 抽成接口以便单测替换。

## 成功标准

- **SC-001**: 30 张 1080p 图片 → A4 PDF，中端机上 ≤ 60 秒完成，输出可被系统 PDF 阅读器打开。
- **SC-002**: 含中文标题、列表、代码块的 Markdown → PDF，无乱码、无断行错误、内容不丢失。
- **SC-003**: 竖图与横图混合时，每页图片宽高比与原图一致（误差 < 1%）。
- **SC-004**: API 24–27 设备选到 HEIC 时给出明确提示且不崩溃（跳过该张，其余正常）。
- **SC-005**: 取消转换后，应用私有目录无残留 `.pdf` 文件。
- **SC-006**: 整个模块**不新增任何权限**（`READ_MEDIA_*` / `WRITE_*` 均不出现）。

## 关键实体

- **PdfSource**：图片（Uri、宽高、方向）或文本（Uri、文件名、字节数）。
- **PdfPageSpec**：页面尺寸、边距、内容类型（图片页 / 文本页）。
- **PdfResult**：路径、字节数、页数。

## 假设

- 用户设备为 Android 7.0（API 24）及以上（宪法 §8）。
- 图片来自相册（Photo Picker 可见范围），不需要访问任意目录。
- 文本文件通过 SAF 选择，应用只读取用户明确选中的那一个文件。
- 输出 PDF 为 **位图页 + 矢量文字**：图片页是位图，文本页文字可选中、可复制（原生 `drawText`）。
- 不做 PDF 加密、水印、页码样式自定义——v1 保持最小可用。

## 范围外（后续再做）

- Word（`.docx` / `.doc`）→ PDF（宪法原定 v1，2026-10-21 决定推迟）
- Excel（`.xls` / `.xlsx`）→ PDF
- PPT → PDF（宪法 §3.3 标记为不做）
- PDF 合并 / 拆分 / 压缩 / 编辑
- OCR、扫描件矫正

**预览与排版（实现后回写，2026-10-21）**

- **FR-020**: 生成完成后 MUST 在应用内预览 PDF 全部页面（横向排列、标注「第 x 页 / 共 n 页」），
  **不得依赖设备是否装有 PDF 阅读器**；【打开】失败时 MUST 明确提示而不是静默。
- **FR-021**: 图片模式 MUST 支持设置「每页张数」（1–6）；排版 MUST 为**纯上下排列**，
  不做左右并排；每张图按原比例缩放居中。
- **FR-022**: 三个功能页（图片压缩 / 视频压缩 / 文件转 PDF）MUST 提供【重置】：
  取消进行中的任务、清空已选输入与参数、回到初始状态；已生成的产物文件 MUST NOT 被删除
  （由"下次生成前清理 + 启动清理"回收）。重复照片清理的重置语义为「只清勾选、保留扫描结果」。
