# Feature Specification: 视频压缩（video-compression）

**Feature Branch**: `feature_foundation1`（目录：`specs/004-video-compression`）

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "视频压缩：选视频、预设分辨率/码率档位、裁剪时长，前台压缩并导出"

## 概述

用户选一个视频 → 选分辨率/码率档位、可裁剪起止时间 → 前台压缩 → 分享或存相册。

三条硬边界（均来自宪法）：

- **完全本地**，不联网、不上传（§1.2）；
- **不引 FFmpeg、不做剪辑**，只做转码/缩放/裁剪时长（§2、§1.2 v1.13）；
- **不申请写权限**：输出写应用私有目录，存相册仅 API ≥ 29 且走 MediaStore（§8）。

本模块独占一个页面（新 tab），不与图片压缩同页（§3.2 的同页规则只适用于图片压缩 + 重复照片清理）。

---

## User Scenarios & Testing

### User Story 1 - 选视频并压缩 (Priority: P1)

用户点【选择视频】，从系统选择器挑一个视频；选择分辨率档位与码率档位后点【开始压缩】，
界面显示进度，完成后可以分享或存相册。

**Why this priority**: 这是功能本体，没有它其余都是装饰。

**Independent Test**: 用一个 30 秒 1080p 视频压缩到 720p/中档，断言输出存在、可播放、
体积明显小于原文件，且时长不变。

**Acceptance Scenarios**:

1. **Given** 未选择视频，**When** 查看界面，**Then** 压缩按钮置灰且提示先选择视频。
2. **Given** 已选择一个 1080p 视频，**When** 点【开始压缩】，**Then** 按钮变为【取消】，且显示进度百分比。
3. **Given** 压缩完成，**When** 查看结果，**Then** 显示「原大小 → 新大小（节省 X%）」与输出时长，并出现【分享】【存相册】。
3a. **Given** 压缩完成，**When** 点【预览结果】，**Then** 弹窗中播放压缩后的视频，并显示「原 → 新 · 时长」，关闭后主页面保持不变（FR-021）。
4. **Given** 压缩进行中，**When** 点【取消】，**Then** 立即停止并删除半成品文件，界面回到可选状态。
5. **Given** 源文件不是视频或已损坏，**When** 尝试压缩，**Then** 提示「无法读取该视频」而不是崩溃。

---

### User Story 2 - 裁剪时长 (Priority: P1)

用户拖动起止滑块选择要保留的片段，输出只包含这段内容。

**Why this priority**: 负责人明确要求；且裁剪本身就能大幅减小体积。

**Independent Test**: 对一个 20 秒视频裁剪为 3–8 秒并压缩，断言输出时长 5 秒（±0.2 秒）。

**Acceptance Scenarios**:

1. **Given** 已选择视频，**When** 拖动起点滑块，**Then** 终点不得早于起点 + 最小片段长度（1 秒）。
2. **Given** 起止已设置，**When** 查看预估，**Then** 预估体积按**裁剪后的时长**计算。
3. **Given** 选区为整段，**When** 压缩，**Then** 等价于不裁剪。

---

### User Story 3 - 档位与体积预估 (Priority: P2)

用户在压缩前就知道大概能压到多大，避免压完才发现不理想。

**Why this priority**: 视频压缩耗时以分钟计，先给预期能减少无效尝试。

**Independent Test**: 断言预估公式与实际输出的偏差在 20% 以内。

**Acceptance Scenarios**:

1. **Given** 已选视频与档位，**When** 参数变化，**Then** 预估体积随档位与裁剪时长实时更新。
2. **Given** 预估结果，**When** 查看，**Then** 同时显示目标分辨率与目标码率（用户能对照）。

---

### 边界情况

- **设备无可用硬件编码器**：明确报错「当前设备不支持该分辨率/编码格式」，不静默降级成软编。
- **存储空间不足**：压缩前按预估体积校验剩余空间，不足则提示。
- **视频超过 30 分钟或 2 GB**：提示「建议先裁剪」，但仍允许用户继续。
- **可变帧率 / 高帧率（60fps）源**：输出按 ≤ 30fps 编码，界面注明。
- **带旋转元数据的竖屏视频**：输出保持正确方向（由转码器处理，不得出现横竖颠倒）。
- **压缩中切到后台**：v1 取消任务（前台限制），界面提示「离开页面会取消」。
- **源视频无音轨**：正常压缩，输出同样无音轨（不得报错）。
- **API ≤ 28**：不显示【存相册】，只保留【分享】。

## Requirements

### Functional Requirements

**模块与边界**

- **FR-001**: MUST 提供独立模块 `:features:video-compression`，仅依赖 `:base`。
- **FR-002**: 本模块 MUST 只对外暴露 `VideoCompressionSection` 与 `VideoCompressionViewModel`，
  页面由 `:app` 组装为一个独立 tab；**不得**与图片压缩同页（§3.2 的同页规则只适用于图片 + 重复清理）。

**技术选型**

- **FR-003**: 压缩 MUST 使用 Media3 Transformer（1.11.1）+ media3-effect，
  MUST NOT 引入 FFmpeg 或调用系统 `ffmpeg` 二进制（宪法 §2 v1.13）。
- **FR-004**: 压缩 SHOULD 走设备硬件编码器。
  **完全没有**可用编码器时 MUST 明确报错并禁止压缩；
  只有软件编码器时 MUST 在界面明示「压缩时长会比较长」并允许用户继续，MUST NOT 静默使用软编。
  <!-- 2026-10-21 修订：原条文为「必须硬编，否则报错」。但模拟器与部分低端设备只有软编，
       强制拒绝会让功能在这些设备上完全不可用，也掩盖了「慢但可用」这一真实选项。
       改为分层要求：无编码器 = 报错；仅软编 = 明示后允许。 -->
- **FR-005**: 输出 MUST 为 MP4（H.264 视频 + AAC 音频）；H.265 仅在设备支持且用户显式选择时使用。

**参数与预估**

- **FR-006**: MUST 提供三档分辨率（480p / 720p / 1080p）与三档码率（高 / 中 / 低），
  码率表按下表执行；分辨率高于源视频时 MUST 按源分辨率封顶（不放大）。
- **FR-007**: 帧率 MUST 上限 30fps；源帧率更低时保持源帧率。
- **FR-008**: 界面 MUST 展示预估体积，计算公式为
  `(视频码率 + 音频码率) × 裁剪后时长 ÷ 8`；预估与实际偏差 MUST ≤ 20%。

**裁剪**

- **FR-009**: MUST 支持设置起止时间，最小区段 1 秒，且不得超出源时长。
- **FR-010**: 裁剪后的时长与预估体积 MUST 实时联动。

**输入输出与权限**

- **FR-011**: 选视频 MUST 使用系统 Photo Picker（`PickVisualMedia.VideoOnly`），不申请读取权限。
- **FR-012**: 输出 MUST 写在应用私有目录 `files/videos/`，分享经 `FileProvider`。
- **FR-013**: 【存相册】MUST 仅在 API ≥ 29 出现，经 MediaStore（`IS_PENDING`）写入；
  MUST NOT 申请 `WRITE_EXTERNAL_STORAGE`（§8）。
- **FR-014**: 取消或失败 MUST 删除半成品文件，不得留下孤立文件。

**交互与错误**

- **FR-015**: 压缩 MUST 显示进度百分比并可取消；离开页面 MUST 取消任务（v1 前台限制）。
- **FR-016**: 错误 MUST 分类提示：源不可读 / 无编码器 / 空间不足 / 转码失败 / 其他。
- **FR-017**: 压缩中 MUST 禁止重复点击，且参数控件置灰。

**预览播放（v1.16 补充）**

- **FR-020**: 选中视频后 MUST NOT 自动播放；用户点击画面区域才开始播放。
  播放中 MUST NOT 显示任何覆盖按钮（避免遮挡画面），暂停或未播放时显示播放图标；
  播放器 MUST 提供底部进度条，播放进度以「裁剪区间」为基准（起点 0%、终点 100%）。
  播放到裁剪终点 MUST 自动停止并回到起点。
- **FR-021**: 压缩完成后 MUST 能预览压缩结果，且与源视频对比：以弹窗形式呈现
  （标题 + 「原大小 → 新大小 · 时长」+ 播放器 + 关闭），主页面状态 MUST NOT 因此改变。
- **FR-022**: 压缩结果不小于源文件时（源本身已很小、档位码率高于源），
  MUST 明确告知「压缩后比原文件大」，并在结果行给出差额；MUST NOT 静默呈现一个"没省空间"的结果。

**质量**

- **FR-018**: 档位到编码参数的映射、预估体积、状态机、取消、错误映射 MUST 有单元测试，
  `./gradlew :features:video-compression:testDebugUnitTest` 通过。
- **FR-019**: ViewModel MUST 继承 `BaseViewModel`（§4）；日志 MUST 用注入的 `LogUtil`（§6）；
  压缩器 MUST 抽成接口以便 JVM 单测替换。

### Key Entities

- **SourceVideo**：id、显示名、字节数、时长、宽高、帧率、有无音轨。
- **CompressionPreset**：分辨率档 + 码率档 → 目标宽高、视频码率、音频码率、帧率上限。
- **TrimRange**：起点 ms、终点 ms（派生时长）。
- **VideoOutcome**：进行中（进度）/ 成功（输出路径、字节数）/ 失败（分类）。

## Success Criteria

- **SC-001**: 30 秒 1080p 视频压到 720p/中档后，体积 ≤ 原文件 50%，且可被系统播放器正常播放。
- **SC-002**: 预估体积与实际输出偏差 ≤ 20%（至少覆盖 480p/720p/1080p 各一例）。
- **SC-003**: 裁剪 5 秒片段，输出时长 5 秒 ±0.2 秒。
- **SC-004**: 取消压缩后，应用私有输出目录无残留文件（含 `.tmp`）。
- **SC-005**: 输出文件在系统相册中可见（API ≥ 29），时长与分辨率正确。
- **SC-006**: 全工程检索本模块与 manifest，`WRITE_EXTERNAL_STORAGE` 出现 0 次。
- **SC-007**: 竖屏（带旋转元数据）视频压缩后方向正确，无横竖颠倒。

## 假设

- **码率表**（H.264 / 音频 AAC 128kbps）：

  | 档位 | 高 | 中 | 低 |
  | --- | --- | --- | --- |
  | 480p | 2.0 Mbps | 1.2 Mbps | 0.7 Mbps |
  | 720p | 4.0 Mbps | 2.5 Mbps | 1.5 Mbps |
  | 1080p | 8.0 Mbps | 5.0 Mbps | 3.0 Mbps |

- **裁剪 UI**：平台 `VideoView` 播放 + `MediaMetadataRetriever` 抽帧做时间轴缩略图；
  **不引入** `media3-exoplayer` / `media3-ui`（只为播放本地文件不值 2–3MB）。
- **单文件**：v1 一次只处理一个视频，不做批量队列。
- **编码格式**：默认 H.264（兼容性优先）；H.265 作为可选项，设备不支持时不显示。
- **音频**：统一重编码为 AAC 128kbps 立体声；无音轨源保持无音轨。
- **前台限制**：不引入 WorkManager 与前台服务，离开页面即取消。
- **范围外**：批量压缩、变速、加水印、字幕、转 GIF、多轨剪辑。
